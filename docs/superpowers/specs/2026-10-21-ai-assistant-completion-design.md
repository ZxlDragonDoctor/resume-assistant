# AI 助手功能补全与测试方案

用户要求：AI 助手模块功能似乎未实现，要求详细实现并测试。用户已确认完整补齐现有内容、ATS、岗位、面试四个页签，在现有界面上完成生成、核对、应用和持久保存流程。

## 已确认的问题与选择

线上千问模型可真实调用。主要缺陷是批量优化没有独立协议与界面，写回回调为空、保存失败仍提示成功，以及模型输出、降级内容和异步请求没有可靠边界。

仅修复空回调不能解决错误建议写入、跨请求污染和失败假成功。采用完整补齐现有功能的方式；保留 FastAPI 同步响应及现有 OpenAI 兼容配置，继续使用现有 Java 简历保存接口。无需新增付费服务或任务队列。

## 行为与数据

- 总结与单条优化提供原文/建议对照，应用操作等待服务器保存。缺少总结模块时仅合并新增模块，保留其他本地草稿。保存失败保留建议并允许重试。
- 批量优化选择一个工作/实习/项目模块，输入最多 30 条带稳定 ID 的要点；返回逐条建议。用户选择需要的结果后写回该模块一次。应用前校验模块、条目位置和原文，过期建议不覆盖新编辑。
- 统一目标岗位解析为用户输入、简历目标岗位、基本信息岗位；不默认填入 Java 或一年经验。只发送有实际正文的可见模块，剔除联系信息，支持既有技能数据格式。
- 四页签保留同一简历的输入和结果；切换简历重置。共享岗位 JD，结果注明输入改变后需重新分析。
- ATS 返回严格的 0–100 整数和建议列表，作为匹配参考。岗位解析和技能匹配分别显示成功或失败结果。面试题依据实际职业与经历，避免全部按软件岗位处理。
- 请求支持取消和重试；后到的旧结果不得进入新的弹窗或简历。服务检测区分检测中、已配置、近期可用、降级和离线。
- AI 调用经现有网关登录鉴权，容器的诊断端口只绑定本机，防止从公网绕过登录直接消耗模型额度。
- 模型输出必须经过类型与范围校验，整个调用有时间上限。无配置或调用失败时提供明确的本地分析标识；提示、改进建议与可应用正文分开。
- 保留原有职责、技能和数字，不把“参与”改成“主导”，不编造工作年限或百分比。翻译接口使用所选语言，无模型时明确不可用。

## 批量协议

请求 `POST /api/ai/optimize-bullets`：`{job_title, bullets:[{id,content}]}`。

响应 data：`{items:[{id,before,after,engine,suggestions?}],engine,notice?,fallbackReason?}`。ID、条数与顺序保持输入一致，before 取原始请求而非模型返回值。

其他能力保留原字段；可新增 `notice`、`suggestions`、`fallbackReason` 元信息。健康状态新增 `modelStatus`，明确配置存在不等同于模型最近调用成功。

## 验收

1. Python 自动化：有效/无效输入、错误模型 JSON、超时降级、模型状态、批量一一对应、翻译语言以及跨职业规则。
2. TypeScript 自动化：文本抽取、岗位解析、要点定位与过期保护、新建总结保留草稿、保存失败和重复操作。
3. 浏览器：总结、单条与批量优化、ATS、岗位、面试的主流程；应用后预览与重新加载一致，页签保留输入，失败重试和迟到结果隔离。
4. 线上使用虚构简历做少量真实模型调用，核对实际引擎和字段；临时账号与简历完成后清理。
5. 构建、提交并更新 AI 服务和前端，保留线上现有配置及可回退镜像。
