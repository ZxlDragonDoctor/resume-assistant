# 模板库分类与模板整理设计

## 背景

模板库目前把版式风格与求职方向混在同一分类维度中。部分模板分类没有中文标签映射，页面会直接显示英文分类键。现有系统种子包含 12 套模板，分类逻辑分散在 SQL 种子、模板服务与简历示例内容选择中。

## 目标

- 一级筛选统一按求职方向组织；版式风格作为模板卡片标签，不再作为一级分类。
- 用户可见的分类名、模板名、说明和标签使用一致的中文表达。
- 重新整理现有 12 套系统模板，使其名称、适用人群、标签与分类一致。
- 新装环境与已有数据库都使用同一套分类；已有模板 ID、配置及用户简历不变。
- 新建模板继续进入“自定义模板”分类，未知历史分类显示为中文“其他”。
- 新建简历仍根据模板所属方向选择对应的示例内容。

## 分类方案

分类键作为内部稳定标识，界面只展示中文名称。

| 分类键 | 页面名称 | 归类说明 |
| --- | --- | --- |
| `general` | 通用求职 | 面向多数岗位的通用简历 |
| `graduate` | 应届校招 | 应届毕业生、实习与校园招聘 |
| `technical` | 技术研发 | 研发工程师、数据分析等技术岗位 |
| `product` | 产品运营 | 产品经理、产品运营与业务增长 |
| `design` | 设计创意 | 视觉、界面与创意岗位 |
| `business` | 商务职能 | 商务、金融、管理及常见职能岗位 |
| `academic` | 学术教育 | 科研、教育与教学岗位 |
| `medical` | 医疗健康 | 医护、医药与健康行业岗位 |
| `custom` | 自定义模板 | 用户保存的自定义模板 |
| `other` | 其他 | 无法识别的历史分类，避免暴露英文键 |

所有筛选结果继续支持关键词搜索。双栏、单栏、侧边栏等版式信息留在模板配置与卡片标签中。

## 模板整理

保留现有 12 套系统模板及其 ID、配置和预览数据，按以下方向重新归类：简约现代→通用求职；经典稳重、商务精英→商务职能；创意新颖、界面设计→设计创意；技术极客、数据分析→技术研发；学术简约、教育培训→学术教育；产品经理→产品运营；应届校招→应届校招；医疗健康→医疗健康。

模板名称、描述和标签改为中文且清楚表达岗位用途；例如将“UI/BI”等英文缩写替换为“界面设计/商业智能”。保留差异化的颜色、字体、版式和模块配置，不将所有模板改成同一套样式。

## 实现边界与数据兼容

- 同步更新 `docs/sql/init.sql` 与 `docs/sql/add-templates.sql`，使新装及按增量脚本补充模板的环境都使用新分类。
- 新增幂等的存量数据库迁移脚本，按系统模板的旧名称与旧分类更新分类、名称、描述和标签；不删除记录、不重建 ID、不覆盖模板配置。
- 模板服务统一归一化新旧分类键，合并旧分类计数，提供中文分类标签；列表筛选兼容迁移前的旧键。未知分类统一归入“其他”。
- 模板创建默认使用 `custom` 分类。
- 更新简历服务的示例内容分派逻辑，支持新分类并兼容旧分类，使已有尚未迁移的数据仍能创建正确的示例简历。
- 模板库页面消费后端分类列表；搜索、模板预览、使用模板和现有交互保持不变。

## 验收标准

1. 模板库筛选项不显示英文分类键，分类含义以求职方向为主。
2. 12 套系统模板均落入上述对应分类，卡片文案和标签为中文且用途明确。
3. 搜索、分类筛选与使用模板流程正常；自定义模板显示为“自定义模板”。
4. 在旧数据库执行迁移后，模板 ID 与配置保持不变，重复执行不产生额外改动。
5. 新旧分类都能正确选择示例简历内容；未知分类显示“其他”且使用安全的通用示例。
6. 前端构建与相关 Java 服务测试通过。

## 发布步骤

部署时先在现有数据库执行新增的幂等迁移脚本，再按仓库 `DEPLOY.md` 的低内存服务器 Compose 配置构建并更新服务。更新后验证模板分类 API、模板库页面及新建简历流程。部署需要当前执行环境具备服务器 SSH 认证。
